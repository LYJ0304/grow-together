# 일기 작성과 사진

본문 → 사진 → 접이식 완료 활동 → 글쓰기 도움 → 저장 순서의 단일 작성 화면이다.
별도의 관찰 메모/재료/결과 편집 단계는 없으며, 본문이 로컬 문장 정리의 관찰 원문이 된다.
완료한 활동만 연결하고 계획 메모를 실제 관찰로 자동 편입하지 않는다.
기존 본문을 문장 정리로 바꾸기 전 확인하며 실패 시 본문을 유지한다. AI 호출은 없다.

## 세션과 저장

기존 `useSessionValue`의 날짜/기록 ID별 초안과 계정 전환 초기화를 유지한다.
본문과 첨부 사진은 탭 왕복/기록 복귀 후 유지되며, 저장 성공 시 초안만 지운다.
미리보기의 저장된 기록은 기존 preview/v2 기기 저장소를 사용한다. 사진은 호환성을 위해
비율을 유지해 최대 960px JPEG로 변환한 data URI 하나를 상태에 보관한다.
앱 재시작 후 미저장 초안 복구/로그인 계정의 기기 영구 자동 저장은 추가하지 않았다.

사진 선택은 기존 목록에 추가한다. 변환 결과가 같은 중복을 제외하고 최대 3장을 유지한다.
선택 취소·형식/용량/변환 오류는 기존 첨부를 유지한다. JPEG/PNG/WebP/HEIC/HEIF,
원본 10MB 이하를 허용하며 플랫폼 디코더가 해당 형식을 지원하지 않으면 오류를 알린다.
웹 파일 선택은 직접 누른 이벤트에서 열고, 생성된 picker object URL은 처리 후 해제한다.
전체 화면 뷰어는 원본 비율, 이전/다음, 닫기, 개별 첨부 제거 확인을 제공한다.
Android 뒤로 가기와 Web ESC로 닫는다. 확대 제스처는 이번 범위에 추가하지 않았다.

기기 저장 실패 시 글/사진을 유지한다. 미리보기 수정은 기존 감정·성장 정보·원문 메타데이터를
보존하며 사진 목록의 명시적 변경만 적용한다. 로그인 수정도 원래 서버 활동 관계를 보존하며
사용자가 남긴 기존 사진 참조와 업로드를 완료한 새 파일 ID를 전송한다. 저장 전 서버 파일 삭제는 하지 않는다.
본문 필수 UI, 로그인 본문 1000자 제한, 날짜/409 충돌·저장 결과 불확실성 처리도 유지한다.

## 로그인 사진 업로드

1. 모바일에서 `POST /api/files/presigned-url`로 업로드 URL과 파일 ID를 받는다.
2. 서명 URL에 JPEG 바이트를 PUT한 뒤 `POST /api/files/{id}/complete`를 호출한다.
   API는 파일 소유자와 객체의 크기·Content-Type을 확인한다.
3. 업로드를 완료한 파일의 `fileId`를 일기 저장 요청에 포함한다.
   일기 조회 시 API는 연결된 사진의 새 GET 서명 URL을 반환한다.

네이티브 실기기에서 사진을 업로드하고 다시 열어보려면
[맥북 staging 가이드](../../api/docs/staging/Development.md)를 따른다.
브라우저 업로드는 사용하는 스토리지의 CORS 설정도 확인한다.

추가/중복/취소/상한/뷰어/삭제/실패 보존/기기 저장 복원/세션 전환을 검사한다.
