# 공통 헤더와 프로필 내비게이션

## 구조와 변경 이유

기존 AppHeader는 프로필 버튼만 우측에 둔 최소 60px 행이었습니다. 일정 화면은 이 아래에 20px 상단 패딩을 추가하고 날짜 영역에서 `25 - insets.top`으로 여백을 다시 보정했습니다. 이는 중복 Safe Area 적용보다는 헤더와 본문의 간격이 누적된 문제였습니다. 오늘 화면은 별도 HeaderTools를 직접 렌더링해 다른 탭과 헤더 구조/시작 위치도 달랐습니다.

- AppHeader는 `[기존 emblem.svg + 같이 키우기] [프로필]`의 최소 56px 수평 행입니다. 일반 글자 크기에서 56px이며 접근성 글자 확대 시 내용에 맞춰 확장할 수 있습니다.
- 로고 32px, 프로필 아바타 34px, 프로필 및 뒤로가기 터치 영역 44px를 사용합니다. 원형 틴트 안의 기존 user.svg와 기존 MotionPressable 피드백을 재사용합니다.
- 화면 제목/설명은 본문에 두며 공통 헤더 안에 큰 페이지 제목을 중복 표시하지 않습니다.
- 일정·질문·리포트 본문 시작 간격은 spacing.sm(8px)로 정리했습니다. 일정의 Safe Area 기반 날짜 패딩 보정은 명시적인 spacing.lg로 바꿨습니다.
- 오늘 화면도 같은 AppHeader를 사용하며 기존 주간/월간 날짜 UI와 최초 진입 모션은 유지합니다. 스크롤 콘텐츠 안에 헤더가 있는 기존 정책도 유지합니다.
- AccountHeader는 AppHeader의 뒤로가기/제목 형태를 재사용합니다. 아이 정보 화면의 독립 텍스트 뒤로가기도 같은 컴포넌트로 교체했습니다. 일기 화면의 기존 뒤로가기 콜백/초안 정책은 변경하지 않았습니다. 일기는 편집 중 프로필·세션 종료로 이동하는 기존 진입점을 rightActions 슬롯으로 유지하며, 다른 계정 상세 화면은 뒤로가기/제목만 표시합니다.

## Safe Area와 스크롤

Safe Area는 기존 각 화면의 SafeAreaView가 담당합니다. AppHeader에서는 insets를 읽거나 추가하지 않습니다. iOS/Android 기본 네이티브 헤더를 추가하지 않으며 공통 React Native 컴포넌트를 사용합니다. 음수 margin이나 absolute positioning으로 상단 여백을 숨기지 않습니다.

기존 최대 너비 600, 하단 5개 탭, FAB, 탭 재선택, 키보드/스크롤/저장 중 차단 로직은 유지합니다. 일정·기록·리포트·질문 헤더는 기존처럼 콘텐츠 스크롤 바깥에 있고 오늘 헤더는 기존처럼 스크롤 안에 있습니다. 화면별 고정/스크롤 정책을 이번 작업에서 일괄 변경하지 않습니다.

## 사용자 정보와 기능 경계

프로필 버튼은 기존 `/mypage`로 이동합니다. 마이페이지의 프로필/아이 정보/로그아웃, 사용자 프로필 조회·수정, 계정별 캐시, 폼 검증은 변경하지 않습니다. 현재 UserProfile 응답에 이미지 필드가 없으므로 사진 URL/Mock 아바타를 새로 만들지 않고 기존 기본 아이콘을 사용합니다. 원격 이미지 요청이 없어 이미지 네트워크 실패에 따른 레이아웃 변경도 없습니다.

`rightActions`는 추후 실제 기능을 연결한 우측 액션을 넣을 수 있는 슬롯입니다. 현재 알림 버튼은 렌더링하지 않습니다. 가족 초대/공유, 실제 알림, 프로필 사진 기능은 별도 API/도메인 설계가 필요한 후속 범위입니다. 미구현 기능을 실제로 사용할 수 있다고 표시하지 않습니다.

## 확인 방법

```sh
npm run typecheck
npm run lint
npm run format:check
MOBILE_URL=http://localhost:8290 BROWSER_EXECUTABLE_PATH=/usr/bin/chromium npm run test:header:ui
```

새 검사는 320/390/430/768/1200px × 5개 탭에서 헤더 높이/브랜드/프로필 터치 영역/단일 렌더링/상단 정렬/가로 넘침/하단 5개 탭을 확인하고, 마이페이지 왕복과 아이 정보 뒤로가기, 글자 확대에서의 넘침을 검사합니다. 기존 일정·메인·프로필·채팅·일기 테스트도 관련 회귀 검증에 사용합니다.

Chromium의 반응형/키보드 어댑터 검사와 Expo 플랫폼 번들 생성은 iOS/Android 실기기 실행이나 Safari/설치형 PWA 실측을 증명하지 않습니다. OS Safe Area, Dynamic Island/상태 표시줄, Android 시스템 뒤로가기, 실제 모바일 키보드, VoiceOver/TalkBack은 기기에서 추가 확인해야 합니다.
